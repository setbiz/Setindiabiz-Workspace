**D1 — O1: Lead_Status on WhatsApp chat leads (CRM workflow rule, no code)**
- Setup › Automation › Workflow Rules › Leads › new rule "SIB WhatsApp - set Establishing Contact".
- Execute on **Create or Edit**, only the first time the criteria are met. "Create only" would miss every SIB-04 chat lead: SalesIQ creates them as Self - Web Chat and the plug turns them into Advt - WhatsApp with an *update* (R15). The plug's update runs with trigger "workflow", so the rule fires on it. **(Superseded by C9: repeat on every edit.)**
- Criteria: Lead Source **is** Advt - WhatsApp **AND** Lead Status **is empty**.
- Instant action: Field update Lead Status = **Establishing Contact**.
- Scope choice for Sanjeev: (a) Advt - WhatsApp only (recommended — SIB-04 scope); (b) also Social - WhatsApp and Self - Web Chat (fixes the 34% gap in R16 for all brands going forward; not retroactive). **(a) built as C5; widened to (b) as C8.**

**D2 — Chat_Attended_By (SalesIQ data workflow + Deluge)**
- New data workflow "SIB-04 chat attended - write Chat_Attended_By": brand Compliance & ACR, module Conversation, events **conversation.attended + conversation.transfer.accepted** (the bot attends first and forwards to the owner, so the human pick-up is normally a transfer accept), no rule, action Deluge.

Payload keys `data.attender.email`, `.is_bot`, `data.visitor.phone` confirmed against Zoho's API doc "Get Details of a Particular Conversation" (SalesIQ REST API v2).
- Workflow 61466000026803029 (2A) and 61466000026746193 stay untouched.
