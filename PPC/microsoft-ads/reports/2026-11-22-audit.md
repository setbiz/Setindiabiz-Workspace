## 2. Why the "Active" campaigns don't deliver

Ruled out from the data:
- **Ads:** Responsive Search Ads show status Active (`AdPerformance`, April). Disapproval would normally stop one campaign, not all four on the same day.
- **Budgets / bids:** both campaigns have daily budgets (₹3,000 / ₹2,000) on Max Clicks.
- **Ad groups / keywords:** enabled ("Pvt Ltd Incorporation - Search", 20 keywords, phrase/exact/one broad).

Not visible through the API, so **the owner needs to check** (Microsoft Advertising → Tools → Billing & payments):
1. Is there an account-level notice ("Account on hold", "Payment declined", "Insufficient funds")?
2. Payment setting: prepay or threshold/postpay? If prepay, was the balance used up around **24 Apr 2026**? If a card, did it expire or fail then?
3. Any outstanding balance or invoice?
4. Also check the Accounts summary for any policy/verification hold (advertiser identity verification).

**Recommendation:** pause "2026 - Company Registration - Main" and "- LP" **before** touching billing, so restoring payment doesn't restart ₹5,000/day of untracked spend on non-compliant copy. Pausing reduces spend, but it is still an account change, so **I need your OK** (Q1).

## 4. Proposed tracking fix (needs approval before any spend)

1. **Goals:** keep a single primary form goal. Point it at tag 26047336 with action `submit`, counting **Unique**. Set Phone/WhatsApp to "All" but **exclude them from bidding** (they're intent, not leads). Leave the paused 2025 goals paused, and archive or delete the unused goals in 150329248 so nobody reads them by mistake.
2. **GTM:** optional hardening. Also fire `submit` on the form-submit event rather than only the `/thank-you` URL, so a broken redirect doesn't hide leads. Add `wa.me` to the WhatsApp trigger in case links change.
3. **Zoho → Microsoft offline conversion import** (judging on won deals):
   - Create an **Offline** goal, e.g. "Zoho Won Deal" (and optionally "Zoho Qualified Lead"), with a 90-day conversion window (maximum 129,600 minutes per the `OfflineConversionGoal` docs). Wait 2 hours after creating it before the first upload.
   - Weekly CSV from a Zoho report: deals won in the past 7 days whose lead has an `msclkid`. Columns: Microsoft Click ID, Conversion Name, Conversion Time (after the click, within 90 days, time zone stated), Conversion Value (professional fee only, if we can separate it), Currency INR.
   - Upload in Microsoft Ads (Tools → Offline conversions → Import). Later, automate with a Zoho Deluge function calling `ApplyOfflineConversions` (1,000 per request). API credentials go in Zoho connections, **never in this repo**.
   - **Click ID only, no hashed email/phone** for now. Hashed contact data is personal data, and the website notice ("used only to respond to your enquiry") doesn't cover ad measurement: IT Act 2000 s. 43A with SPDI Rules 2011 r. 4–5, now in force; DPDP Act 2023 ss. 4–6 and 8 apply once the DPDP Rules 2025 commence (≈13 May 2027, verify on meity.gov.in).
4. **Fix CRM attribution** (finding 5). Find out why 35 leads outside the delivery window are `Advt - Microsoft`: a persisted landing URL, manual tagging, a pre-rule backfill, or a SEO-Bing mix-up. Until then, judge Microsoft on **leads with an `msclkid` created within 30 days of a click date**. I can run this check once you confirm the Zoho API names of the Source URL / First Page fields (Q4).
5. **Bidding during verification:** Max Clicks or Enhanced CPC (both still supported for Search per the current Bing Ads API docs). Don't move to Maximize Conversions until UET and the offline goal both show real conversions. Note that you **can't add** a Max CPC cap to a non-portfolio Max Clicks campaign any more (API breaking change), so if we want a CPC ceiling we'd use Enhanced CPC with keyword bids, or a portfolio strategy.
